# Карточка действия: первый изолированный блок

Это первый блок переработки, НЕ полная игра и НЕ готовый апдейт. Исходные main.py, language.py, systems.py, models.py и world.json не заменены. Новая механика ещё не подключена к ходу недели.

## Реализовано и проверено отдельно

- ActionCard: 25 типов, адресат, тема/позиция, способ, место/событие, ресурсы, цель, известные факты, подтверждение.
- Валидация JSON, чисел, версии и диапазонов фрагментов исходного текста.
- Чистый расчёт соответствия: тема/адресат, канал/адресат, место/время, способ/цель, ресурсы/масштаб, последовательность, повтор. Для каждого коэффициента возвращается причина.
- Бонус за авторские, синтаксически связанные поля и известные факты; предел +20 к шансу и ×1,5 к эффекту. Длина текста не награждается, перефразирование не создаёт новизну содержания.
- Поля помощника не дают авторского бонуса.
- Нулевой охват/ресурсы не спасаются творческим бонусом или нижним пределом шанса.
- Новая отдельная память принимает только подтверждённые карточки, поддерживает забывание и сброс при обновлении словарей. Старая память пока не заменена.

## Проверка

```bash
python -m unittest discover -s Kocto/tests -p 'test_semantic_actions.py' -v
```

Локально прошли 37 unit-тестов. Один проверяет 300 комбинаций структурированных карточек. Это НЕ корпус 300 русских фраз и НЕ доказательство точности парсера 85/80/95%.

Числа tests/fixtures/semantic_rules.json — тестовая фикстура, не откалиброванный баланс. При интеграции настройки должны поступать из world.json["semantic_actions"].

CI настроен для unit-тестов и существующего smoke_test.py на Python 3.11 и 3.13. До получения результата CI прохождение полного smoke-теста не подтверждено.

## Требования к подключению

1. Синтаксический разбор создаёт карточку, а отсутствующие поля остаются пустыми. Нельзя восстанавливать смысл из тегов.
2. Evidence.linked означает связь поля с действием, установленную парсером. Совпадение слова, диапазон символов и подтверждение игроком сами по себе её не доказывают. Этот модуль не устанавливает её автоматически.
3. Правка карточки снимает подтверждение. В память и очередь попадает только подтверждённая карточка.
4. Профиль адресата, доступные ресурсы, известные факты, события и история берутся из GameState, а не выдумываются из текста.
5. Предпросмотр и итог используют один алгоритм и снимок контекста. Бросок и внесение изменений остаются обязанностью systems.py. effect — скаляр, не полный набор изменений мира.
6. Полномочия, поддержка типа действия, цена, риск, обещания и последствия проверяются отдельно. Наличие типа в схеме не означает реализацию в игре.
7. Причины подключаются к журналу. Старые теги отключаются только после интеграционных проверок.
8. Побочные реакции других адресатов требуют отдельной модели; текущий расчёт принимает одного адресата.

## Ещё не выполнено

- Новый парсер, разбор отрицаний и корпус русских фраз.
- Правка и подтверждение «Понял как…», подключение к очереди и ходу недели.
- Досье города, желания/страхи/каналы, 10–15 ситуаций-задач.
- Содержательные обещания, память NPC/соперников, цепочки и пресса.
- Три навыка с общим стартовым пулом 90.
- Выборы на 24/72 неделе, итог на 96-й; проверка продолжения после поражения.
- Экономика, пассивная стратегия, риск и грязные методы, симуляции баланса.
- Выбор/удаление сохранений и резервная копия недели.
- Редактируемая раскладка, обучение и помощник вне игрового мира.
- Исправление старых событий/данных, плейтест 3–5 игроков и полный выпуск.

Изменения предназначены для отдельной рабочей ветки. Не сливать как готовый большой апдейт.
